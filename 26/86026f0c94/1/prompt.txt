## Summary

Gmail API email summarization agents typically use OAuth 2.0 for secure read-only access, apply lightweight ML or rule-based priority classification, and aggregate results into concise digests. Handling API rate limits requires careful quota management, batching, and scheduling to avoid disruptions.

## Key findings

- **Gmail API OAuth for reading emails**:  
  - Use OAuth 2.0 with scope `https://www.googleapis.com/auth/gmail.readonly` (no modify/delete permissions).  
  - Implement the authorization code flow for user accounts; for service accounts (e.g., G Suite domain-wide delegation), use JWT-based authentication.  
  - Store refresh tokens securely (e.g., encrypted database) and handle token expiration by refreshing automatically.  
  - Example: Use Google’s client libraries (Python, Node.js) to manage the flow—explicitly request offline access to get a refresh token.

- **Common patterns for email priority classification**:  
  - **Rule-based**: Filter by sender (e.g., VIP list, known domains), subject keywords (“urgent”, “action required”), or email labels (e.g., “IMPORTANT” label set by Gmail).  
  - **ML-based**: Train a binary classifier (e.g., using scikit-learn or TensorFlow) on features like email body length, reply count, sender domain, and time since last email; use lightweight models for near-real-time inference.  
  - **Hybrid**: Apply rules first (fast), then pass remaining emails to a lightweight ML model (e.g., logistic regression or small BERT variant) for finer-grained ranking.  
  - Note: Gmail’s own priority inbox (via “IMPORTANT” label) can be used as a high-quality signal without custom ML.

- **Best practices for email digest formatting**:  
  - Keep each email summary to 1–2 lines: sender, subject, date, and a 1-sentence AI-generated summary (use GPT-3.5/4 or similar for abstracts).  
  - Group emails by priority or thread (e.g., “High Priority”, “From VIPs”, “All Others”).  
  - Use clear separators (e.g., `## High Priority` markdown headers) and limit total digest to 10–15 entries to avoid overwhelming the user.  
  - Include actionable indicators: flags for important attachments, action verbs (“Please review by Friday”), and links to open email in Gmail.

- **How hourly email digest agents typically handle rate limits**:  
  - Gmail API quotas: 1 billion queries per day per project, but 25 queries per second per user (varies; check current docs).  
  - **Pacing**: Schedule the agent to run once per hour, but stagger individual user API calls across the hour (e.g., use a queue or random delays) to avoid bursts.  
  - **Caching**: Store last-fetch timestamps and only fetch new emails since last check (use `q:after:<timestamp>` or history API for incremental sync).  
  - **Error handling**: Implement exponential backoff on 429 (rate limit exceeded) responses; retry up to 3 times.  
  - **Batching**: Use the `users.messages.batchGet` endpoint to fetch multiple message details in one request (reduces per-message quota consumption).

- **Authentication**: Use OAuth 2.0 with `gmail.readonly` scope and store refresh tokens encrypted; implement token refresh logic in the agent’s startup routine to avoid interruptions.
